# Finch CLI

ابزار خط فرمان `finch` هر آنچه **خارج** از یک app در حال اجرا رخ می‌دهد را مدیریت می‌کند: قالب‌بندی پروژه جدید، نصب dependency ها، اجرای سرور توسعه، کامپایل باینری production، و تولید فایل‌های boilerplate. این ابزار دستورات رایج دارت را پوشش می‌دهد و وظایف مختص فینچ را نیز به آن اضافه می‌کند.

مجموعه دومی از دستورات نیز وجود دارد که **درون** یک app در حال اجرا در دسترس هستند (`migrate`، `route`، `language`، `info`، به‌علاوه هر دستور سفارشی که ثبت می‌کنید) — این‌ها در [Commands](24.commands.md) پوشش داده شده‌اند و بخشی از `finch -h` در زیر نیستند. این تمایز مهم است: `finch <command>` پیش از وجود app شما اجرا می‌شود، درحالی‌که یک دستور app-runtime نمونه واقعی `FinchApp` را اجرا می‌کند و می‌تواند به route ها، دیتابیس، و پیکربندی app دسترسی داشته باشد. برای دیدن نحوه ارتباط این دو، به [Running an Application](4.run_app.md) (بخش «ارسال آرگومان‌ها») مراجعه کنید.

## نصب

```bash
dart pub global activate finch
```

## مثال‌های رایج

### ساخت پروژه جدید با قالب example

```bash
finch create -n my_app -t example
```

### مشاهده قالب‌های موجود پروژه

```bash
finch templates
```

لیست قالب‌های رسمی (هر یک متکی به یک ریپازیتوری GitHub با نام `<template>-finch-docker`) را واکشی می‌کند که می‌توانید آن را به `finch create -t <key>` پاس دهید.

### اجرای سرور توسعه با file watcher

دستور `serve` فایل‌های widget و زبان را رصد می‌کند و آن‌ها را بدون راه‌اندازی مجدد سرور بارگذاری می‌کند:

```bash
finch serve
```

یا با تعیین نقطه ورود:

```bash
finch serve -p lib/serve.dart
```

در پشت صحنه، `run`/`serve` برنامه شما را به‌عنوان یک child process اجرا می‌کنند (`dart run [--enable-asserts] [vm-service flags] <path> <args>`) و یک پرامپت تعاملی کوچک را در ترمینال شما روی آن نگه می‌دارند — کلید `r` را برای راه‌اندازی مجدد child process، `c` را برای پاک کردن صفحه، `i` را برای نمایش نسخه/اطلاعات دارت، `h` را برای نمایش تاریخچه دستورات، و `q` را برای خروج فشار دهید. `serve` علاوه بر این یک WebSocket را روی `--terminalPort` (پیش‌فرض `8282`) باز می‌کند که همین پرامپت را منعکس می‌کند و [local debugger](23.debugging.md) در مرورگر به آن متصل می‌شود.

### ساخت باینری برای production

```bash
finch build -a lib/app.dart -o ./build/app
```

### تولید فایل‌های boilerplate

```bash
finch make:controller -n Product
finch make:service -n Payment
finch make:middleware -n RateLimit
finch make:migration -n add_users_table
finch make:migration -n add_users_table -s   # برای SQLite به‌جای MySQL
```

### ساخت فایل مهاجرت

```bash
finch migrate --create --name add_users_table
finch migrate --create --name add_users_table --sqlite
```

این فقط یک فایل مهاجرت خالی و جدید را در مسیر مهاجرت پیکربندی‌شده شما ایجاد می‌کند (برای `pathMigrationMySQL`/`pathMigrationSQLite` به [Configuration](3.configuration.md) مراجعه کنید) — تغییرات واقعی schema/داده را همان‌طور که در [Database Migration](25.database_migration.md) شرح داده شده، در آن بنویسید.

## اجرای مهاجرت‌ها

اجرای مهاجرت‌ها یک **دستور app-runtime** است، نه یک flag سطح بالای `finch` — باید درون `FinchApp` واقعی شما اجرا شود تا بتواند از اتصال‌های دیتابیس پیکربندی‌شده شما استفاده کند. آن را با پاس دادن `--args` از طریق `finch run`/`finch serve`، یا با فراخوانی مستقیم نقطه ورود برنامه خود با `dart run` اجرا کنید:

```bash
# اعمال مهاجرت‌های MySQL معلق
finch run --args="migrate --init"

# اعمال مهاجرت‌های SQLite معلق
finch run --args="migrate_sqlite --init"

# ترکیب هر دو در یک فراخوانی با --and (همان‌طور که در Dockerfile نمونه استفاده شده)
finch run --args="migrate --init --and migrate_sqlite --init"

# معادل آن، بدون عبور از finch CLI اصلاً
dart run lib/app.dart migrate --init
```

برای فهرست کامل دستورات app-runtime (`route`، `language`، `info`، و هر دستور سفارشی که ثبت می‌کنید) به [Commands](24.commands.md) و برای نوشتن و rollback کردن مهاجرت‌ها به [Database Migration](25.database_migration.md) مراجعه کنید.

### بررسی مسیرهای ثبت‌شده

`route` نیز یک دستور app-runtime است، بنابراین به همان روش فراخوانی می‌شود:

```bash
# نمای جدولی
finch run --args="route"

# با ستون‌های اضافه (controller، function، middlewares، ...)
finch run --args="route --detail"

# به‌صورت JSON، مثلاً برای انتقال به ابزار دیگر
finch run --args="route --json"
```
