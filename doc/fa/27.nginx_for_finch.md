# Nginx برای فینچ

Nginx به عنوان یک reverse proxy جلوی برنامه فینچ قرار می‌گیرد. این کار عملکرد SSL، فایل‌های استاتیک و load balancing را ممکن می‌سازد.

## مفهوم Reverse Proxy

```
Client → Nginx (پورت 80/443) → Finch (پورت 8080)
```

Nginx درخواست‌ها را می‌پذیرد، SSL را پردازش می‌کند و آن‌ها را به Finch که در پشت اجرا می‌شود ارسال می‌کند.

## پیکربندی Nginx

```nginx
upstream finch_app {
    server finch:8080;
}

server {
    listen 80;
    server_name example.com www.example.com;

    # فایل‌های استاتیک مستقیماً سرو می‌شوند
    location /public/ {
        alias /app/public/;
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # همه چیز دیگر به فینچ می‌رود
    location / {
        proxy_pass http://finch_app;
        proxy_set_header Host \$host;
        proxy_set_header X-Real-IP \$remote_addr;
        proxy_set_header X-Forwarded-For \$proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto \$scheme;

        # پشتیبانی از WebSocket
        proxy_http_version 1.1;
        proxy_set_header Upgrade \$http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

## پشتیبانی از HTTPS

```nginx
server {
    listen 443 ssl;
    server_name example.com;

    ssl_certificate     /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;

    location / {
        proxy_pass http://finch_app;
        proxy_set_header X-Forwarded-Proto https;
        # ... بقیه header ها
    }
}

# هدایت HTTP به HTTPS
server {
    listen 80;
    server_name example.com;
    return 301 https://\$host\$request_uri;
}
```

## محدودیت اندازهٔ درخواست و Rate Limit

Finch بدنهٔ درخواست‌ها را در حافظه نگه می‌دارد؛ بنابراین علاوه بر Nginx خودش هم سقف اعمال می‌کند. هر دو را فعال کنید: Nginx خط دفاع اول است و Finch وقتی Nginx دور زده شود یا اشتباه تنظیم شده باشد (مثلاً پورت `8085` مستقیم publish شده باشد) از سرور محافظت می‌کند.

| لایه | تنظیم | کاربرد |
|---|---|---|
| Finch | `maxBodySize` (پیش‌فرض ۱۰ مگابایت) | درخواستی که `Content-Length` بزرگ‌تر دارد یا بدنهٔ stream شده‌اش از سقف بگذرد، `413 Payload Too Large` می‌گیرد و بدنه دور ریخته می‌شود |
| Finch | `maxSocketMessageSize` (پیش‌فرض ۱ مگابایت) | پیام WebSocket بزرگ‌تر، اتصال را با کد `1009` می‌بندد |
| Nginx | `client_max_body_size` | بدنه‌های بزرگ را قبل از رسیدن به Dart رد می‌کند. برای مسیرهای آپلود آن را **برابر یا بیشتر** از `maxBodySize` فینچ بگذارید |
| Nginx | `client_header_timeout` و `client_body_timeout` | کلاینت‌های کند (Slowloris و آپلود کند) را قطع می‌کند |
| Nginx | `limit_req` و `limit_conn` | Rate limit به‌ازای هر IP (Finch ابزار داخلی rate limit ندارد) |

```nginx
limit_req_zone  $binary_remote_addr zone=finch_req:10m rate=30r/s;
limit_conn_zone $binary_remote_addr zone=finch_conn:10m;

server {
    client_max_body_size  20M;
    client_header_timeout 15s;
    client_body_timeout   30s;

    limit_req  zone=finch_req burst=100 nodelay;
    limit_req_status 429;
    limit_conn finch_conn 30;
    limit_conn_status 429;
}
```

> **نکته:** پورت Finch (`8085`) را روی اینترنت publish نکنید و فقط Nginx را در دسترس بگذارید. سقف داخلی Finch یک شبکهٔ ایمنی است، نه جایگزین آن.

## دستورالعمل `try_files`

برای برنامه‌های Single Page Application از `try_files` استفاده کنید:

```nginx
location / {
    try_files \$uri \$uri/ @finch;
}

location @finch {
    proxy_pass http://finch_app;
}
```
